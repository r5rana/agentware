<a id="1-layered-layout"></a>
## 1. Layered layout

`scripts/agentware` is a **thin entrypoint** (a `sys.path` bootstrap and a
dispatch tail — nothing else, and it may not grow past its 120-line cap). Every
line of domain code lives in `scripts/agentware_lib/`, organised into layers so
the dependency direction is visible in the filesystem itself:

```
scripts/agentware_lib/
  core/        paths · config · dates · frontmatter · gitio · kblayout · orgkeys · routing
               orgidentity · projectcontext · embedderapi · …
               ↳ small, STABLE, feature-independent primitives. Imports nothing above.
  knowledge/   index · curation · graph · privacy · proposals · attach · worklog · …
               ↳ the KB system of record: index CRUD/validate/rebuild, learn/decide, worklog gate.
  retrieval/   corpus · bm25 · acr · hybrid · vectorcache · skillpin · ledger
               regressiongate · goldfixture · longmemeval · bench · recallcmd · evalcmd · …
               ↳ THE MOAT: tokenize/BM25/RRF/ACR + eval/ledger/gates + SWE bench.
  ops/         sessionparse · metrics · derive · loop* · alerts · fleet · orglint · team
               steering · releasegate · planlint · planauthor · audit · kbgit · scaffold* · …
               ↳ operational surfaces: telemetry, org/fleet, lints/gates, plan authoring, KB git.
  features/    fanout · mcp · dream* · skills · proposals · *cmd · graphdag · migratecmd · …
               ↳ optional/pluggable capabilities; may import any lower layer, never the reverse.
  verbs.py     ← the DISCOVERY leaf: walks the package, collects every `__verbs__`.
  cli.py       ← the ASSEMBLY leaf: builds the argparse tree + main() + whereami.
```

Every subpackage has an `__init__.py` (the py3.7 floor has no namespace-package
support under `unittest discover`). Each module opens with four contract lines:
`Owns:` / `Does NOT own:` (naming the module that does) / `Layer deps:` /
`Fan-in:` (blast radius, regenerated by `tests/_manifest_gen.py --sync-fanin`).

**There is no monolith and no facade.** The 20k-line `scripts/agentware` script
and the `_FACADE_MODULES` re-export loop that briefly replaced it are both gone;
a caller reaches a symbol by importing the module that owns it.

<a id="3-layer-contract"></a>
## 3. The layer contract

A **module-level upward import is a test failure, not a style note**
(`R-MOD-02`, `tests/gates/test_modularity_rules.py`):

<!-- BEGIN GENERATED: layer-direction (python3 tests/_doc_sync.py --write) -->

| Layer | May import at module level | Imports nothing from |
|-------|----------------------------|----------------------|
| `core` | _nothing_ | `knowledge`, `retrieval`, `ops`, `features`, `cli` |
| `knowledge` | `core` | `retrieval`, `ops`, `features`, `cli` |
| `retrieval` | `core`, `knowledge` | `ops`, `features`, `cli` |
| `ops` | `core`, `knowledge`, `retrieval` | `features`, `cli` |
| `features` | `core`, `knowledge`, `ops`, `retrieval` | `cli` |
| `cli` | `core`, `features`, `knowledge`, `ops`, `retrieval` | _nothing_ |

<!-- END GENERATED: layer-direction -->

**Why the direction is worth a gate.** Folder names are free; a folder name that
is not enforced is a comment. The value of `core/` is not that the word appears
in the path — it is the guarantee that reading a `core` module never sends you
upward into a feature. That guarantee is what lets one agent own one module and
change it without reading the rest of the package, which is the entire point of
the split. The moment one upward import is tolerated, the layers stop being a
partial order and the only honest map of the code is the whole code.

**The escape hatch, and its price.** An upward edge that genuinely cannot be
removed is carried by a **function-local import with a stated reason**, never a
module-level one — so the module-level graph stays acyclic and the package still
imports from a cold interpreter:

```bash
PYTHONPATH=scripts python3 -c "import agentware_lib.cli"
```

Prefer, in order: (1) move the shared symbol DOWN to the layer both callers may
import, (2) move the module to the layer it actually belongs in, (3) the lazy
import. The pre-existing residual — modules that already carry a module-level
upward edge — is declared in `tests/fixtures/modularity-debt.json`, is
shrink-only, and is owned by a named task. A new one may not join it.

**No module may be named** `utils`, `helpers`, `common`, `misc` or `shared`
(`R-MOD-05`): a module named for what it is NOT has no boundary, so it grows
until it is the monolith again under a friendlier name.

<a id="4-thin-entrypoint"></a>
## 4. The thin entrypoint

`scripts/agentware` is only two things:

1. **A `sys.path` bootstrap** — puts `scripts/` on `sys.path` so
   `import agentware_lib…` resolves in every load mode: direct exec, the
   `tests/_fixtures.load_cli` `SourceFileLoader`, and the dashboard sidecar.
2. **The GUARDED dispatch tail** — `if __name__ == "__main__":
   sys.exit(main(sys.argv[1:]))`. The guard is **non-negotiable**: `load_cli()`
   `exec_module()`s this file, so a bare `sys.exit(...)` would run `main()` at
   import time and raise `SystemExit` inside every test that loads it.

It also stays mode `0755`: `agentware.sh` guards eleven call sites on
`[[ -x scripts/agentware ]]` and every one of them FAILS OPEN, so a lost
executable bit turns gates green instead of red. After any rewrite:
`chmod +x scripts/agentware`.

Nothing of substance is defined here and nothing here may grow — the whole
surface belongs in `agentware_lib`, and the 120-line entrypoint cap in §6 is
what keeps that true.

<a id="5-verb-registration"></a>
## 5. Verb registration — one file, one verb

**Each module declares the verbs it owns; nothing else knows the list.** The
declaration is a module-level `__verbs__` dunder of
`(verb, order_key, registrar_attr)` triples:

```python
__verbs__ = (("scaffold", 4500, "register_scaffold"),)
```

`agentware_lib.verbs` walks the package in sorted dotted-name order, collects
every declaration, refuses a duplicate verb or a duplicate order key (naming
BOTH claimant modules), and hands `agentware_lib.cli.assemble_parser` the
ordered `(verb, module, attr)` registration it iterates. Each registrar has the
signature `register_<verb>(sub, fmt_parent)` and lives beside its handler.

- **The order key is the `--help` byte contract.** It is sparse (steps of 100)
  so a verb can be inserted between two others without renumbering; reordering
  existing keys changes `--help` bytes and reddens the whole help-golden corpus.
- **Why a dunder and not `VERBS`.** An UPPER_SNAKE module constant is recorded by
  `tests/_constant_differ.py` as a tracked constant, so forty modules declaring a
  same-named constant with forty different literals would arrive as a
  `multi_literal` finding storm. `__verbs__` is excluded by that normalisation's
  own rule and is the language's idiom for module metadata.
- **Why a package walk and not entry points.** agentware is clone-and-go: there
  is no distribution metadata, so `entry_points()` returns EMPTY and the CLI
  would present zero commands with no error.
- **Completeness is a two-witness gate.** `catalog/modules.json` records each
  module's `verbs` array read from the AST **without importing**; discovery finds
  the same declarations **by importing**; `tests/gates/test_verb_discovery.py`
  asserts the two agree. A declaration only one witness can see — built at
  runtime, or in a module that fails to import — is loud.

This replaced a frozen single-file registry, which was a monolith in miniature:
it centralised a decision that belongs beside the code, and it was the one file
every concurrent fanout lane edited.

| Scope | Cap |

residual lives in `tests/fixtures/ceiling-debt.json`, is shrink-only in BOTH
directions (an undeclared violation fails AND a row the tree no longer produces
fails), and is owned by a named task.

<a id="7-extensibility-contract"></a>
## 7. The extensibility contract

The point of the split: many agents each own one module and extend the package
without reading all of it. **All package edits are self-extension** (`R-PKG-03`)
— after any of the below, run `scripts/agentware steering lint`,
`scripts/agentware eval --record --gate` and `scripts/agentware gate release`
(`R-PKG-04..06`).

**The fastest path is not to hand-write any of this.** `agentware scaffold new`
emits a compliant unit and all its hand-maintained wiring, then runs the two
generators; `agentware scaffold check` audits an already-written unit and is
usable in CI. Read §9 for what each of its five checks means.

### (i) Add a SUBCOMMAND (a new top-level verb)

1. In the OWNING module `scripts/agentware_lib/<layer>/<mod>.py`, define
   `def cmd_<name>(args):` returning an int exit code.
2. In the SAME module define `def register_<verb>(sub, fmt_parent):` — the
   signature is mandatory even when `--format` is unused. Body:
   `p = sub.add_parser("<verb>", parents=[fmt_parent], …)`, add arguments, then
   `p.set_defaults(func=cmd_<name>)`.
3. In the SAME module declare `__verbs__ = (("<verb>", <order>, "register_<verb>"),)`
   with a sparse order key at the display position the verb should occupy.
   **That is the whole registration** — no central file to edit (§5).
4. Regenerate the manifest: `python3 tests/_manifest_gen.py --write`.
5. Add the curated parity row in `tests/_parity_curated.py` and regenerate:
   `python3 tests/_parity_manifest.py --out` (`R-MOD-08`).
6. Update the two independent pins in `tests/gates/test_parser_golden.py`
   (`EXPECTED_VERBS`, `EXPECTED_SURFACES`) at the same position, then re-capture
   the help fixtures: `COLUMNS=80 python3 tests/_help_golden.py --write`.
7. Add `tests/unit/<layer>/test_<mod>.py` (`R-MOD-06`) and a router row in
   `scripts/agentware_lib/README.md`.

### (ii) Add a MODULE

1. Create `scripts/agentware_lib/<layer>/<name>.py`, layer ∈
   `core|knowledge|retrieval|ops|features`.
2. Give it the four docstring contract lines (`Owns:` / `Does NOT own:` /
   `Layer deps:` / `Fan-in:`).
3. Keep every module-level import DOWNWARD per §3; make any genuinely upward
   edge a function-local import with a stated reason.
4. End the file with `_EXPORTS = [ … ]` and `__all__ = list(_EXPORTS)` —
   "what cross-module consumers need", not "every public name".
5. Regenerate the manifest — never hand-edit `catalog/modules.json`
   (`R-MOD-07`): `python3 tests/_manifest_gen.py --write`.
6. Add `tests/unit/<layer>/test_<name>.py` and the router row, then
   `python3 tests/_doc_sync.py --write` for this document's map.
7. If the module owns a verb, ALSO run recipe (i).

**Extend an existing verb's module rather than adding one** (`R-MOD-09`); add a
module only for a domain no module owns. **Land the unit WHOLE in one change**
(`R-MOD-11`): module, verb declaration, manifest entry, mirrored unit file and
parity row. If a change fits no layer, STOP and record the `> DECISION:` before
writing code (`R-MOD-12`).

### (iii) The ownership rule

One domain per module, one owner per symbol. No symbol appears in two modules'
`_EXPORTS`. Mutable globals (caches, locks) live in exactly ONE module and are
read late-bound through the module alias (`alias.X`), so monkeypatching the
owner propagates to every consumer.

### (iv) The NO-FORWARD-REFERENCE rule

A symbol used as a **default-arg value** cannot be lazily imported (defaults
evaluate at import time), so it must live in a module importable at module level
from its user. Two stdlib AST/bytecode gates enforce it:

```bash
python3 tests/_ast_forward_edges.py scripts/agentware $(find scripts/agentware_lib -name '*.py')
python3 tests/_global_resolve.py   scripts/agentware $(find scripts/agentware_lib -name '*.py')
```

| `tests/gates/test_verb_discovery.py` | The AST witness (manifest) and the import witness (discovery) agree on the whole verb surface and its order. | (runs in the suite) |

capability that no row claims is invisible to the ledger, which is why
`R-MOD-08` obliges a curated row for it — `surface:*` rows are generated from a
pre-merge fixture and therefore cannot cover anything added afterwards.

<a id="10-determinism-moat"></a>
## 10. The determinism moat

Retrieval is byte-identical across runs — no LLM, no RNG, no network and no
wall-clock in ranking. The invariants and where they live:

- **INV-1 (deterministic ranking)** — `retrieval/*`; ranking functions take
  `as_of`/`today` as parameters, and the org frontmatter keys are excluded from
  `_entry_doc_text` (`R-ORG-08`), so org metadata can never move a score.
- **INV-2 (read-only reporting)** — `ops/freshness`, `ops/alerts`,
  `knowledge/proposals` and `ops/releasegate` never mutate the KB or the index.
- **INV-6 (stdlib-only static imports)** — asserted over the entrypoint and every
  `agentware_lib/**` module; the `scripts/` sidecars (dashboard, embedders) are
  excluded by name, not by accident.
- **INV-7 (regression gate)** — `retrieval/regressiongate` (`eval --gate`).

A change that adds a dependency, reads the clock inside a ranking function, or
writes during a report breaks one of these, and the invariant suite says which.
